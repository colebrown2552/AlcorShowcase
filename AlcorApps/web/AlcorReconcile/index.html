How matching works

  • One row per key. The report lists each key once, sorted, with how many rows each file has for it.
  • Keys. Leading and trailing spaces are removed and inner runs of spaces become one space. Matching ignores case unless you turn on case-sensitive keys. There is no fuzzy matching. A row with a blank key is never matched. It is listed as a blank key with its file and row number, for example “left row 2 has blank business-key column(s): invoice”, so you can fix it at the source.
  • Duplicates. If a key is in both files and either file has it more than once, the key is reported as a duplicate and its amounts are not compared. A key found in only one file is reported as missing from the other file even if it repeats; the Left rows and Right rows columns show how many times it appears.
  • Amounts. The decimal point is “.”. Commas, spaces, and $, €, £, ¥ signs are removed, so “1,234.50” reads as 1234.50 and “1,5” reads as 15. Parentheses mean a negative amount. Values are compared exactly, without floating-point rounding. NaN and Infinity are not amounts: that key is reported as an invalid amount, like any unreadable cell, and the rest of the comparison still runs. An amount too large for exact decimal arithmetic stops the whole comparison; the message names the key so you can fix that cell.
  • Tolerance. A difference equal to the tolerance still counts as matched.
  • Files. Comma-separated UTF-8 text with a header row, up to 10 MB each. Quoted fields, embedded commas and line breaks, and a UTF-8 byte-order mark are handled. Semicolon- or tab-separated files, Excel workbooks and Windows-1252 text are refused with a message; save them as “CSV UTF-8 (Comma delimited)”.

These rules match Alcor Industries’ alcor-reconcile 0.1.0 Python package, and both are checked against the same test cases. The browser tool differs in a few places: it refuses a key or amount column whose header name appears more than once, reads files up to 10 MB with up to 1,000 columns, stops with an error where the Python package would crash, and marks formula-like text cells in the CSV export as text (plain negative amounts such as -30.00 stay numbers).
